# FTPS 证书方案（计划）

> 状态：**未实现**。存档于 2026-11-04。当前行为是「首次启动自动生成，之后无法管理」。

## 现状

`FtpsOptions.LoadOrCreateCert()` 在首次启动时生成 10 年自签证书：

- 主体：`CN=监听地址`（监听 `0.0.0.0` 时用主机名）
- SAN：监听地址写死时只含该 IP；监听 `0.0.0.0` 时含本机全部 IPv4 + `localhost`
- 存放：`service\ftps\ftps_cert.pfx`，**无密码**
- 算法：RSA 2048 / SHA256

可用，但有三个现实麻烦。

## 三个问题

| 问题 | 表现 | 影响 |
|---|---|---|
| **手机不信任自签证书** | 手机会话直接 TLS 握手失败 | 扫码也连不上 |
| **换网络后证书不匹配** | 换了网段，IP 不在 SAN 里 | 必须删 pfx 重新生成 |
| **无法更换/续期** | 界面上没有入口 | 只能手工删文件 |

其中第一条最致命：Android 7+ 起，App **默认只信任系统 CA 和 App 自带 CA**，用户手动安装的 CA 证书对 App 也不生效（需要 App 里配 `networkSecurityConfig` 声明信任用户证书）。所以“让用户装个证书”这条路在手机上并不顺畅。

## 四条备选路线

### A. 导出证书给客户端安装（基础能力）

UI 加「导出证书」：把 pfx 里的公钥导出成 `.cer`，方便在 PC 上装进「受信任的根证书」。

- 优点：实现简单，PC 端浏览器/VLC 立刻可用
- 缺点：**手机侧仍有 Android 7+ 的限制**，需要 App 配合

### B. 二维码下发指纹，客户端做 TOFU（推荐与 A 一起做）

二维码载荷里加证书 SHA256 指纹：

```json
{ "type": "ftps", "host": "...", "port": 21, "cert_fp": "SHA256:AbCdEf..." }
```

App 首次连接时接受任意证书但记录指纹，之后每次比对；指纹变了就阻断并提示。

- 优点：**不需要用户装证书**，安全性靠“首次信任 + 变更告警”
- 参照：SSH 模块的 `fp` 字段已经是这个思路，两个模块行为一致
- 缺点：首次连接没有中间人防护（局域网场景可接受）

### C. 界面里「重新生成证书」

换网络后一键重生成（自动把当前所有本机 IP 写进 SAN）。

- 优点：解决“换网段连不上”，实现只要几十行
- 注意：重生成后指纹变化，客户端需重新信任

### D. 局域网自建 CA（进阶，暂不做）

用一张自建根 CA 签发服务证书，手机装一次根 CA 即可长期信任。

- 优点：正规做法，多设备一次搞定
- 缺点：手机侧同样受 Android 7+ 限制；且要维护 CA 私钥，复杂度陡增

## 建议的实施顺序

1. **B（指纹下发）** —— 解决“能不能连上”的核心问题，投入最小
2. **A（导出证书）** —— PC 端体验补齐
3. **C（重新生成）** —— 换网络后的自救手段
4. D 暂不做，除非将来要做多设备统一信任

## 技术要点备忘

- 导出公钥：`cert.Export(X509ContentType.Cert)` → 写 `.cer`
- 指纹：`cert.GetCertHashString(HashAlgorithmName.SHA256)`
- SAN 里放 IP 时注意：证书里必须是 `IPAddress` 类型条目，写成 DNS 名会校验失败
- 重生成前要先确保服务已停止，否则 pfx 文件被占用
- 二维码载荷加字段属于**协议变更**，App 端需要同步解析

## 与现有代码的接点

| 位置 | 改动 |
|---|---|
| `FtpsOptions.LoadOrCreateCert` | 抽出「按当前 IP 生成」，供 UI 调用 |
| `FtpsView`（基本设置卡片） | 加「证书指纹」显示 + 「导出」/「重新生成」按钮 |
| `GenerateQr` | 载荷加 `cert_fp` 字段 |
| App 端 | 解析 `cert_fp`，实现 TOFU 校验 |
